# Jarvis for Roy

A macOS personal assistant with a native workspace, on-device voice input, spoken answers, background analysis, and approval-gated desktop actions. Inspired by the [Awesome Jarvis blueprint](https://github.com/csells/awesome-jarvis/blob/main/blueprint.md); this is an independent implementation, not a fork of a complete Jarvis product.

**Status: first-version source-build preview.** It is not a signed/notarized consumer download, an always-listening assistant, or an unrestricted computer-control agent. Native build and microphone verification require macOS; see the verification notes below rather than assuming a green backend test covers the app.

## What it does

- Native SwiftUI workspace with real task states, results, execution events, approvals, and cancellation.
- Microphone input using Apple's **on-device** speech recognition when supported by the current device and language. Audio is not uploaded by Jarvis. Review the transcript, then send it. Text input always remains available.
- Optional spoken results using macOS speech synthesis. Starting the microphone interrupts speech. Stop speech independently, or use **Stop all / ⌘.** to request cancellation of agent work too.
- Local [eve](https://github.com/vercel/eve) agent runtime with a separate analyst for drafting and reasoning. Independent tasks can run while you keep using the interface.
- Three explicit, approval-gated actions: open an HTTPS webpage in the default browser, save a new note in Jarvis's own notes folder, and save a requested memory.
- View and delete saved memories. No synthetic tasks, canned model answers, fake execution logs, or simulated integration badges.

## Requirements

| Dependency | Requirement |
| --- | --- |
| macOS | 14 Sonoma or newer |
| Compiler | Xcode Command Line Tools with Swift 5.9+ (`xcode-select --install`) |
| Runtime | [Node.js 24 LTS](https://nodejs.org/en/download) and npm on `PATH` |
| Model access | A [Vercel AI Gateway API key](https://vercel.com/docs/ai-gateway/authentication-and-byok) and model credits |
| Voice | Microphone and Speech Recognition permission; on-device recognition support for your language |

Docker, a Vercel deployment, a database account, and a separate speech-provider key are not required. Cloud inference is metered by the model provider; there is no included inference credit.

## Setup and launch

```sh
git clone https://github.com/Backpacked333/jarvis-roy.git
cd jarvis-roy
./scripts/setup-macos.sh
./scripts/run-macos.sh
```

The launcher prompts for your Gateway key without echoing it if `AI_GATEWAY_API_KEY` is not already set. It does not save the key to disk. Keep the launch terminal open while using Jarvis. Quitting the app stops the local services. Launch through the script, not by double-clicking the app bundle: the script supplies a fresh local authentication token and starts the runtime.

Allow microphone and speech access only when you want voice input. If denied, enable **Jarvis** under **System Settings → Privacy & Security → Microphone / Speech Recognition**, then relaunch. On-device recognition availability varies; the app shows an explicit error and does not silently switch to cloud transcription.

### Try it

1. Ask: “Draft a concise plan for a weekly personal review.” Watch the task and any analyst delegation in Activity.
2. Ask: “Remember that I prefer short, actionable answers.” Inspect the proposed memory, then approve or deny it. Check Memory.
3. Ask: “Save a note titled Weekly review with a five-step checklist.” Approve the exact content. The result identifies the saved file.
4. Ask: “Open https://github.com/csells/awesome-jarvis.” Deny first; no browser should open. Submit again and approve to open it.
5. Start work and press **⌘.** Check for cancellation confirmation. This does not undo actions that already completed.

Each submitted message creates an **independent task**, not a continuation of the previous conversation. Include the context needed for that task. Spoken approvals, continuous conversation, wake-word detection, calendar/email integrations, screen capture, and coding-agent control are not implemented in this version.

## Configuration

| Environment variable | Meaning |
| --- | --- |
| `AI_GATEWAY_API_KEY` | Server-only inference credential; prompted for if missing |
| `JARVIS_MODEL` | Gateway model identifier; defaults to `openai/gpt-4.1-mini` |
| `JARVIS_DATA_DIR` | Local task metadata, approved notes, and memories; defaults to `~/Library/Application Support/JarvisRoy` |
| `JARVIS_LOCAL_TOKEN` | Ephemeral local service credential generated by the launcher; never commit or share it |

The runtime listens only on `127.0.0.1:39201`; the native-client bridge listens only on `127.0.0.1:39202`. Both require the local credential. Do not expose these ports through tunnels, proxies, port forwarding, or a public deployment. The bridge rejects browser-origin requests; it is not a web API for arbitrary websites.

## Architecture

```text
SwiftUI desktop
  ├─ Speech framework → on-device transcript → user reviews and submits
  ├─ AVSpeechSynthesizer ← selected task's answer
  └─ authenticated loopback bridge
       ├─ task metadata / progress / approvals / cancellation
       └─ eve durable agent runtime
            ├─ Gateway model (cloud)
            ├─ analyst specialist (no desktop tools)
            └─ explicit tools → approval → narrow local action
```

The UI does not wait for a model turn to finish before remaining usable. The optional default eve tools are disabled in both agents: there is **no shell, unrestricted file access, browser automation, or default web fetch**. Approval is enforced in tool configuration, not merely in a prompt. URL opening uses an argument-array process invocation, not a shell command; notes use generated filenames rather than model-selected paths.

eve is pinned to a release candidate because that is the available documented runtime used by this project. Treat upgrades as compatibility changes: its persisted workflow protocol and event schema can change. Stop services and back up local state before upgrading.

## Privacy and storage

- Cloud model requests include submitted text, model context, recalled memories, and tool results. **This is not an offline assistant.** Review Gateway/provider retention policies before sending sensitive data.
- Speech recognition is explicitly on-device only. No always-on microphone or screen capture.
- Gateway credentials stay in process environment; the UI receives only the local bridge token.
- Local task history and durable workflow data can contain personal text. They are not encrypted by this app; use FileVault and an appropriate macOS account boundary.
- Deleting a memory removes its saved preference, not copies already included in prior conversations or provider logs.
- For a full local reset, quit Jarvis and its launcher, then remove the Jarvis data directory and `runtime/.eve` in this checkout. Back up approved notes first. Provider-side logs require separate handling according to provider policy.
- Stop all is a cancellation request, **not rollback**. The displayed status is the source of truth. Already opened pages or saved files remain.

## Development and verification

Backend checks:

```sh
cd runtime
npm ci
npm run typecheck
npm test
npm run build
```

Native build (on a Mac):

```sh
./scripts/build-macos.sh
```

Manual native acceptance: launch, verify offline/error states, submit a real model task, approve and deny each action, cancel running work, relaunch to inspect persisted history, delete a memory, then test microphone allow/deny and spoken-result interruption. A microphone test requires real audio input; a successful compile does not prove voice works.

### Repository layout

- `macos/` — Swift Package, native UI, local API client, speech controller, bundle metadata.
- `runtime/agent/` — agent instructions, specialist, and restricted tools.
- `runtime/` — local bridge, persistence, backend tests, pinned dependencies.
- `scripts/` — source-build setup, app bundling, and local service lifecycle.

No developer signing identity, notarization credentials, private keys, or production account credentials are included. Distribution outside a source-build workflow needs Apple signing/notarization and native acceptance testing first.
